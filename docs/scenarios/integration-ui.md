# 통합 UI 설계 — Soft Gating · 기록 교차 · 삼각별 완성

**캐릭터 스토리텔링 기반 전시 안내 서비스 / 세 노선 통합 시스템**
**국립중앙과학관 전시운영정책과**
**기준일: 2026. 8. 13.**

> 이 문서는 샘이·탐이·꿈이 세 노선을 하나의 시스템으로 묶는 저장·재방문·통합 결말 설계다.
> common-framework.md(§4.2 세계관 회수 지점, §6 기록 평준화 금지, §7 재방문·교차 원칙)를 구현한다.

---

## 0. 목적과 전제

이 UI의 목적은 하나다 — **한 번 온 관람객이 다시 오게 만드는 것.** 단, common-framework의 제약을 지킨다.

- **한 노선만 해도 완결된다** (Hard Gating 금지). 통합 결말은 강제가 아니라 보너스다.
- **물리적 전시 중복으로 재방문시키지 않는다.** 재방문 동력은 저장된 기록의 교차로 만든다.
- **세계관을 몰라도 각 노선은 이해된다.**

핵심 장치는 **삼각별**이다. 삼각별의 세 꼭짓점 = 세 노선(과거·현재·미래). 한 노선 완주 = 꼭짓점 하나 봉인. 세 꼭짓점이 모두 켜지면 나로호에서 통합 후일담이 열린다. 카드가 곧 삼각별이며, 삼각별을 완성하려면 카드를 챙겨와야 한다 — 강제가 아니라 유혹.

## 1. 저장 원칙과 카드 데이터 구조

### 1.1 저장 매체 역할

| 저장 매체 | 저장 정보 | 기록 시점 | 지속성 |
|---|---|---|---|
| **캐릭터 카드 (정본)** | 카드 버전, 선택 캐릭터, 완주 노선, 세 빛 상태, 노선별 결과 요약 | 안내데스크·나로호 리더 | 정본·영구 |
| **폰의 진행 URL (임시)** | 현재 노선, 완료 거점, 선택 결과, 미션 조각, 마지막 위치 | QR 거점마다 | 임시 |
| 서버 DB | 사용하지 않음 | — | 없음 |

### 1.2 기본 원칙

- 개인정보와 상세 행동기록을 카드에 넣지 않는다.
- 폰에는 현재 노선을 이어가기 위한 정보만 둔다.
- 노선을 완주하면 폰의 결과를 **나로호 리더에서 카드에 요약해 봉인**한다.
- 완주 후 폰의 세부 기록은 없어져도 카드의 완주 상태에는 영향이 없다.
- **카드 분실 시 이전 기록을 복원하지 않는 것을 기본**으로 한다. (별도 회원정보·중앙 DB를 만들지 않기 위함)

### 1.3 카드에 저장할 최소 정보

NFC 카드 용량을 고려해 문장·상세 응답은 저장하지 않고 **코드값만** 기록한다.

| 필드 | 예시 | 기능 |
|---|---|---|
| 데이터 버전 | `02` | 향후 구조 변경 대응 |
| 카드 상태 | `ACTIVE` | 정상 카드 확인 |
| 캐릭터 ID | `S` / `T` / `K` | 현재 선택 캐릭터 |
| 노선 완주 비트 | `101` | 샘이·탐이·꿈이 완주 여부 |
| 샘이 결과 코드 | `S03` | 마지막에 선택한 미래 질문 |
| 탐이 결과 코드 | `T12` | 확인한 조건·수정 유형 |
| 꿈이 결과 코드 | `K21` | 선택한 바람·메시지 유형 |
| 통합 결말 상태 | `0` / `1` | Bonus Epilogue 개방·열람 여부 |
| Checksum | 짧은 검증값 | 데이터 손상·오입력 확인 |

**노선 완주 비트(3bit)** — 자리 순서 = 샘이·탐이·꿈이

- `001`: 샘이만 완주
- `010`: 탐이만 완주
- `100`: 꿈이만 완주
- `111`: 세 노선 완주

세부 미션 전체를 카드에 담지 않는다. 노선별 핵심 선택을 각각 1~2byte 코드로 요약하면 용량은 문제되지 않는다.

> **주의**: 실제 저장 가능 용량·쓰기 방식은 카드 종류, NDEF 사용 여부, UID 활용 방식, 리더 펌웨어에 따라 달라진다. 카드 모델과 현재 데이터 구조를 확인한 뒤 **Byte-level Schema를 확정**해야 한다. (§11 TODO)

## 2. 안내데스크 시작·재방문 Flow

- **새 카드 발급**: 카드 초기화(데이터 버전·`ACTIVE`), 캐릭터 선택 기록(S/T/K).
- **재방문 인식**: 카드를 읽어 완주 비트를 확인하고, 이어할 노선/새 노선을 안내한다.
- 리더는 **읽기·초기화·캐릭터 선택 기록**을 담당한다. (카드 쓰기의 시작점)

---

## 3. 중간 QR 세션 구조

- 중간 거점은 **QR로 폰(임시 세션)에만** 진행 상황을 저장한다. **카드 쓰기 없음.**
- 폰이 보유: 현재 노선, 완료 거점, 선택 결과, 미션 조각, 마지막 위치.
- 중간 거점에 리더를 추가하지 않는다 → 운영·장애 대응이 단순해진다.

---

## 4. 나로호 봉인 Flow와 2단 결말

나로호 리더가 **읽기·완주 쓰기**를 담당한다. 노선 결과를 폰→카드로 요약 봉인하고, 해당 꼭짓점(세 빛)을 갱신한다.

### 4.1 1단계 — 캐릭터별 독립 결말 (해당 노선만 완주해도 반드시 열림)

| 캐릭터 | 나로호에서 얻는 독립 결말 |
|---|---|
| 샘이 | 남겨진 증거와 기록이 다음 탐사를 가능하게 한다 |
| 탐이 | 한 조건의 성공만으로 안다고 할 수 없으며 실제 환경에서 다시 확인해야 한다 |
| 꿈이 | 미래는 정해진 예언이 아니라 현재의 상상과 이어진 도전에서 시작된다 |

이 결말만으로도 해당 노선의 경험은 완결된다. 다른 노선 미완료를 실패·부족으로 표현하지 않는다.

### 4.2 2단계 — 세 노선 통합 후일담 (완주 비트 `111`일 때만)

기존 결말을 대체하지 않고 그 뒤에 약 **40~60초의 Bonus Epilogue**가 붙는다. (본편 §7 참조)

## 5. Soft Gating 화면 상태

"잠김", "미완성", "실패" 표현을 쓰지 않는다. 빈 꼭짓점은 회색으로 남기되 자물쇠를 표시하지 않는다.

**한 노선 완주**
> 과거의 기록이 완성됐어요.
> 현재와 미래의 기록은 아직 만나지 못했어요.

- 다른 캐릭터를 만날 수 있다는 사실만 보여준다.

**두 노선 완주**
> 두 개의 시간이 연결됐어요.
> 또 다른 친구는 같은 나로호에서 무엇을 발견할까요?

- 남은 캐릭터·노선의 질문을 짧게 보여준다. 즉시 새 노선을 시작하라고 강요하지 않는다.

**세 노선 완주**
> 세 개의 시간 기록이 모두 모였습니다.
> 통합 후일담을 시작합니다.

---

## 6. 기록 교차 대사 규칙

이전 완주 기록은 **다음 노선의 핵심 대본을 바꾸지 않는다.** 도입·공유 전시품에서 **한두 줄의 보너스 대사만** 연다. (Hard Gating 아님)

| 현재 방문 | 카드 선행 기록 | 보너스 대사 |
|---|---|---|
| 꿈이·천체관 | 탐이 완주 | "탐이와는 달의 환경이 어떻게 다른지 확인했군요. 이번에는 그 먼 곳에 생각을 보내볼까요?" |
| 탐이·천체관 | 꿈이 완주 | "꿈이와 달에 메시지를 보냈구나. 실제 임무를 만들려면 그곳의 조건부터 확인해야 해." |
| 탐이·나로호 | 샘이 완주 | "샘이가 찾은 기록이 여기까지 이어졌네. 이제 이 기술을 다른 환경에서 확인할 차례야." |
| 꿈이·나로호 | 샘이·탐이 완주 | "남겨진 기록과 다시 확인하는 방법이 모였어요. 이제 그 위에 아직 없는 가능성을 더해볼까요?" |

선행 노선 기록이 없어도 본편은 그대로 진행한다. Hard Gating이 아니라 기록 기반 보너스 회수다.

## 7. 세 노선 통합 후일담 — 「세 개의 시간이 만나는 순간」

완주 비트 `111`일 때만, 나로호 독립 결말 뒤에 붙는다.

### 7.1 카드 인식 → 삼각별 완주 연출

나로호 리더가 카드를 읽으면 세 기록을 확인한다.

> 과거의 기록: 확인 / 현재의 확인: 확인 / 미래의 시작: 확인

화면의 삼각형 세 꼭짓점이 차례로 켜진다. 꼭짓점마다 단순한 '빛'이 아니라 **관람객이 실제로 남긴 기록**이 표시된다.

| 꼭짓점 | 카드에서 불러오는 내용 |
|---|---|
| 샘이·과거 | 관람객이 남기기로 한 질문 |
| 탐이·현재 | 관람객이 확인한 조건 또는 수정 기록 |
| 꿈이·미래 | 관람객이 선택한 바람과 전송한 메시지 |

### 7.2 세 캐릭터 합류 (세 기록을 하나로 평준화하지 않음)

> 샘이: "남겨진 기록이 있었기 때문에 여기까지 올 수 있었어."
> 탐이: "여기까지 왔다고 끝은 아니야. 다른 곳에서는 다시 확인해야 해."
> 꿈이: "그리고 아직 없는 길은 누군가 먼저 상상해야 시작돼요."

화면에는 세 기록이 각자 다른 꼭짓점에 남은 채, 가운데에 나로호가 나타난다.

> 남겨진 것을 이해하고, 지금의 결과를 확인하며, 아직 없는 가능성을 상상한다.

이 문장은 프로젝트 전체의 통합 문장으로 사용할 수 있으나, **개별 노선에서는 반복하지 않는다.**

### 7.3 "삼각별이 되살아난다"의 의미 (얇은 회수)

- 삼각별을 실제 전시사건의 원인으로 만들지 않는다.
- 세 캐릭터의 결핍 때문에 별이 망가졌다고도 하지 않는다.
- 통합 후일담에서만 다음처럼 얇게 회수한다.

> 꿈이: "세 시간의 기록이 모두 이어졌어요."
> 탐이: "이제 삼각별에서도 무엇이 달라졌는지 확인할 수 있겠어."
> 샘이: "우리가 찾은 기록을 가지고 돌아가자."
>
> 삼각별 귀환 경로: 복원

관람객이 별을 마법처럼 치료한 것이 아니라, **세 캐릭터가 삼각별로 돌아갈 수 있는 기록과 방법을 완성**했다고 표현한다. 세계관이 노선을 묶으면서도 전시과학을 침범하지 않는다.

## 8. 관람객이 실제로 얻는 것

**필수 보상**
- 카드의 세 꼭짓점 완성 상태
- 세 캐릭터 합류 영상
- 통합 여정 요약 화면
- 삼각별 귀환 경로 복원 상태

**선택형 보상**
- 완성 화면을 스마트폰에 저장할 수 있는 이미지 (카드 데이터에서 그 자리에서 생성, 개인정보·서버 저장 불필요)
- 완주 인증용 QR 화면
- 캐릭터 3종이 함께 있는 디지털 배지

**물리적 추가 보상**
- 별도의 종이 도장·새 카드는 **필수로 만들지 않는다.** 이미 카드 자체가 수집물이자 재방문 매체다. 물리 보상을 더하면 운영·재고·배부 관리가 늘어난다.

## 9. 리더 배치

| 장소 | 카드 동작 | 목적 |
|---|---|---|
| 안내데스크 | 읽기·초기화·캐릭터 선택 기록 | 새 여정 시작 또는 재방문 인식 |
| 중간 거점 | 카드 쓰기 없음 | QR로 폰 임시 진행 |
| 나로호 | 읽기·완주 쓰기 | 노선 결과 봉인·세 빛 갱신 |

카드 쓰기가 안내데스크와 나로호로 제한되므로 운영과 장애 대응이 단순하다.

## 10. 예외 처리

| 상황 | 처리 |
|---|---|
| 폰 진행정보는 있으나 카드 분실 | 새 카드로 현재 노선만 이어갈지 안내데스크에서 선택. 이전 완주 기록은 복원하지 않음 |
| 카드에는 완주가 있으나 폰 진행정보 없음 | 완주 기록 유지. 새 노선 시작 가능 |
| 나로호 리더 쓰기 실패 | 폰에 미봉인 상태 보존 후 안내데스크 또는 동일 리더에서 재시도 |
| 동일 노선 재완주 | 기존 완주 비트 유지, 결과 코드 갱신 여부를 관람객이 선택 |
| 세 노선 완주 후 재방문 | 통합 후일담 다시 보기와 개별 노선 다시 하기 제공 |

### 권고

> "삼각별을 완성하면 무엇을 얻는가?"의 답은 물리 상품보다 다음이 적절하다.
> **카드에 세 시간의 기록이 완성되고, 나로호에서 세 캐릭터의 통합 후일담과 삼각별 귀환 경로가 열린다.**

카드 자체가 소장품이자 재방문 매체다. 한 노선 완주도 충분한 결말을 제공하고, 세 노선 완주는 더 넓은 의미를 보여주는 보너스로 둔다. 이 구조라면 Soft Gating·기록 교차·삼각별 세계관·재방문 동력이 하나의 시스템으로 결합된다.
